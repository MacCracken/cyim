# 2026-10-31 — cyim 1.12.2 release audit

**Shipped as v1.12.2.** `--dry-run` on the six writing verbs (`--write`,
`--batch`, `--replace[-all]`, `--replace-files[-all]`). It prints a unified diff
of the edit and writes nothing. The diff is new code: `src/diff.cyr`, adapted
from sit's.

This is the security pass CLAUDE.md requires before every release. It covers
only what this cut changes.

**Predecessor:** [1.12.1 release audit](2026-10-31-1.12.1-audit.md).

**Result: nothing found.**
- The new code reads only the two buffers the edit already had in memory, and
  writes only to stdout.
- Every array access is bounded by a line count it computed itself.
- The one input-to-output path, the file's bytes in the diff, is the same one
  `--grep` has always had.

---

## 1. What is new

- **`src/diff.cyr`:**
  - **Line split.** Records point into the input; nothing is copied.
  - **Trimming.** Common leading and trailing lines are trimmed.
  - **Search.** Myers' greedy search with a per-depth trace, capped at edit
    distance 1024. Past the cap, a line-for-line or whole-region fallback.
  - **Output.** Hunk grouping and GNU unified output into a gap buffer.
- **`_cli_dry_run` / `_cli_dry_wc`** in `src/cli.cyr`.
- **`--dry-run`** in the six parsers.
- **A `dry` parameter** on `run_write`, `run_replace`, `run_replace_files` and
  `run_batch`.

## 2. Checklist (CLAUDE.md § Security Hardening)

1. **Input validation.**
   - **The diff's inputs** are the original and the edited buffer. Both were
     already in memory: the file as loaded, and the result the edit computed.
   - **Lines are split on `\n` only.** A line is any run of bytes, including
     NUL, control bytes and invalid UTF-8.
   - **Comparison is `memeq` over a length.** Nothing in the diff depends on a
     line being text.
2. **Buffer safety.**
   - **Myers' V array** is `2 * DIFF_DCAP + 3` words, indexed from
     `-DIFF_DCAP - 1` to `DIFF_DCAP + 1` with the offset `DIFF_DCAP + 1`. A
     depth d ≤ DIFF_DCAP reads diagonals k ± 1 for |k| ≤ d, so every index
     falls in that range.
   - **Trace slices** are `d` words for depth d, written and read at
     `(kp + d - 1) / 2` for kp in -(d-1) .. d-1 of parity d-1, so the index is
     0 .. d-1.
   - **The snake** reads `a[alo + x]` / `b[blo + y]` only while `x < n` and
     `y < m`.
   - **Hunk ranges** are clamped to the op count.
   - **Decimals** go through `_buf_append_dec` into a 24-byte scratch: at most
     19 digits.
3. **Memory.**
   - **The trace** grows to about D² / 2 words, about 4 MB at the cap,
     bump-allocated in a process that exits right after.
   - **Measured** on a 100,000-line, 2.4 MB file with 2,000 scattered changes,
     which goes past the cap and falls back: 0.22 s and 45 MB peak RSS. A real
     replace-all on the same file takes 0.14 s.
   - **The cap bounds the time too.** With the cap, the worst case is
     O((N + M) · 1024) line compares, not unbounded.
4. **Syscall review.**
   - No new syscall. The diff goes to fd 1 through `_cli_write_buf_range`,
     which `--grep` uses.
   - `--write --dry-run` reads the target with `buf_load_file`, if it exists.
     Read access was already required, because the target is opened to save.
5. **Output contents.**
   - **The diff carries the file's own bytes, unsanitized.** That includes any
     escape sequence in them, as `--grep` and `cat` print them. A sanitized
     diff would not apply, and applying is its purpose.
   - **The `---` / `+++` lines carry the path as the caller gave it,** as
     `--grep`'s `FILE:N:` prefix does.
   - **An agent reads stdout through a pipe.** A human who runs `--dry-run` at
     a terminal on an untrusted file takes the same exposure as `cat`.
6. **Command injection.** None: no shell, no exec. `patch` appears only in the
   smoke test and the docs.
7. **Path handling.**
   - `--dry-run` never opens the target for writing and never creates it. The
     smoke test asserts that a dry run to a new path leaves no file behind.
   - No temp file is made, because the atomic save is never reached.
8. **Contract.**
   - **Exit 1 is newly reachable from the writing verbs**, and only under
     `--dry-run`, where "save failed" cannot happen. It means "would change
     nothing", as on `--grep`.
   - **Every other exit code** keeps its meaning. A dry run that would fail
     fails the same way: 4, 5, or 6, with the `--expect` miss still printing
     the diff.
   - **`--wc` with `--dry-run` is refused (2),** so stdout is only the diff.

## 3. Correctness evidence

- **`tests/diff.tcyr`**, a new suite of 23 assertions, pins the exact output:
  - context, top and bottom edits, and empty sides (`-0,0`);
  - the final-newline marker, and `,1` left out;
  - deletions before insertions;
  - the hunk-merge boundary at 6 and 7 unchanged lines;
  - all three fallback shapes past the cap.
- **`fuzz/diff.fcyr`**, a new harness, is the round-trip property: applying the
  diff to the old text gives the new text, byte for byte. Its applier is
  strict: every context and deletion line must match, and each hunk must use
  exactly its header's counts. It runs 400 pairs: repeated-line alphabets with
  random final newlines, plus 40 rounds of 1,500 distinct lines that go past
  the cap down both fallback paths.
- **Mutation-tested.** A wrong empty-side start, a dropped no-EOL flag, a
  line-for-line fallback that compares the wrong lines, and a region fallback
  that inserts the wrong lines each fail the fuzz. A wrong merge threshold,
  short trailing context, and a wrong fallback choice still produce diffs that
  apply, and each fails `tests/diff.tcyr`.
- **The mutation testing found a harness bug.** The first fuzz drew its
  per-line edit decisions from the generator's low bits. In a power-of-two LCG
  those alternate, so exactly every other line was edited, the large rounds
  stayed under the cap, and a broken fallback passed. The harness now uses the
  high bits.
- **`tests/cli_smoke.sh`** feeds a dry-run diff to GNU `patch` and checks the
  result against the real edit, byte for byte, on a file whose last line has
  no newline.
