# 2026-05-07 — cyim 1.5.x closeout audit

**Shipped as v1.5.2 (last patch of the 1.5.x cycle).**

"Run a closeout pass before tagging X.Y.0 or X.0.0. Ship as the
last patch of the current minor"). The 1.4.x → 1.5.x arc lit up
the full LSP user-visible surface end-to-end (cyim-lsp folded

[`docs/development/roadmap.md`](../development/roadmap.md)'s

1.6.0. F-CO-2 is informational (wait-for-third-consumer); F-CO-1,
F-CO-3, F-CO-4 are actionable patches.

(end-of-M7 triage: 0 CRITICAL / 0 HIGH / 0 MEDIUM at v1.0.0).

**Goal:** prove the 1.4.x / 1.5.x additive ABI extensions held

## 3. Dead code audit

`CYRIUS_DCE=1 cyrius build` reports 359 dead symbols. Breakdown:

- **stdlib auto-prepend**: ~280 symbols (`alloc_*`, `assert_*`,
  `bench_*`, `fmt_*`, `str_*`, `Str_*`, `vec_*`, `map_*`, `sys_*`,
  `fs_*`, `unicode_*`, `result_*`, etc.) — DCE strips because
  cyim's main loop doesn't reach them. Expected.
- **niyama public API**: ~25 symbols (`niyama_bre_match`,
  `niyama_pcre_match`, `niyama_re2_match`, `niyama_vim_match`,
  `niyama_fuzzy_*`, etc.) — niyama's regex flavors are exposed
  for direct ABI use; cyim's flat dispatch uses the per-flavor
  `_re_*` helpers in `src/cli.cyr` instead. Expected.
- **cyim-lsp public API**: ~10 symbols (`jsonrpc_version`,
  `lsp_client_proc`, `lsp_client_start`, `lsp_diags_count`,
  `lsp_proc_kill`, `lsp_state_buf`, `lsp_state_count`,
  `lsp_state_version`) — public bundle API not all consumed by
  the consumer-side glue. Expected (frozen ABI surface).
- **cyim plugin ABI surface**: ~6 symbols (`plugin_last_diags`,
  `plugin_list_active`, `plugin_list_count`, `plugin_list_index`,
  `plugin_list_items`, `plugin_register_normal_key`,
  `diag_line` / `diag_msg` / `diag_severity`) — public ABI per
  ADR 0004 freeze. Tests + future consumers reach them.
- **cyim source ABI surface**: ~10 symbols (`buf_cap`, `buf_gap`,
  `editor_cfg_line_numbers`, `editor_cfg_tabstop`,
  `editor_last_error`, `editor_set_mode`, `editor_drive`,
  `editor_run`, `visual_selection_hi`, `visual_selection_lo`,
  `window_count_leaves`) — accessors / alternate driver entries
  used by tests, kept as ABI per ADR 0004.

**Cyim-source true-dead**: 0 functions to remove. The dead-code
floor is the **public ABI surface** plus stdlib that DCE strips
correctly. No actionable cleanup.

**Result:** ✅ floor accepted.

## 4. Refactor pass

Two patterns accreted across 1.4.x → 1.5.x worth flagging, both
below the rule-of-three threshold:

**Pattern A — "load uri + jump to lc":** present in
`_cyim_lsp_ex_goto_def` cross-file branch (1.4.3) and
`_cyim_lsp_on_ref_select` (1.5.1). Two instances; identical
modulo error message ("definition" vs. "reference"). Per cyim's
CLAUDE.md "wait for the third instance" rule, defer extraction
of `_cyim_lsp_jump_to_uri_lc(s, uri, line, char, err_msg)` until
a 3rd consumer (e.g. `:lsp-implementation`, `:lsp-type-definition`).

**Pattern B — "materialize buffer to flat (ptr, len)":** present
3 times in `_cyim_lsp_ex_*` handlers — already abstracted into
`_cyim_lsp_buf_to_flat(b, len_out)`. ✓ already DRY.

**Finding F-CO-2 (LOW):** Pattern A is at 2 instances. Note for
future: when cyim-lsp grows `:lsp-implementation` or
`:lsp-type-definition`, extract the helper instead of copy-paste.

**Result:** ✅ no refactor warranted at 1.5.x cut.

## 5. Code review pass

Walked the 1.4.0..1.5.1 diff end-to-end across the touched
modules:

- `src/plugin.cyr` — registry additions (prefix-keys vec,
  list-display state), public registrations, internal helpers,
  list-mode lifecycle (`_plugin_list_dismiss`/`_next`/`_prev`/
  `_select`)
- `src/mode.cyr` — generalized prefix dispatch, KEY_G recognition,
  ACT_MOVE_FILE_START constant, list-mode interception at top of
  `editor_dispatch`
- `src/motion.cyr` — `motion_apply` ACT_MOVE_FILE_START → `motion_file_start`
- `src/render.cyr` — `_render_list_overlay` overlay helper,
  invoked from both `render_frame` and `_render_frame_multi`
  paths
- `src/command.cyr` — `_buf_load_file_into_active` extraction
  (shared between `:e <file>` and `plugin_buf_load_file`)
- `src/plugins/lsp_glue.cyr` — gd/gr handlers, cross-file
  goto-def, refs parser + label builder + on_select + module
  payload globals
- `tests/plugin.tcyr` — +52 assertions across 21 new test groups

**Finding F-CO-3 (LOW, defense-in-depth):** When a user types
`g` (latches `KEY_G` prefix) and a plugin synchronously calls
`plugin_list_display` before the user's next keystroke, the
prefix stays latched while the picker is active. On dismiss,
the next NORMAL key still sees the prefix and tries to resolve
it. In practice unreachable today: the only plugin_list_display
call site is `:lsp-find-refs` / `gr` ex-command paths, which
complete dispatch before yielding to next-key. Future hardening:
clear the prefix on `plugin_list_display` entry.

**Other guards reviewed:**
- `_plugin_list_select(s)` — dismisses BEFORE firing on_select
  (chained pickers safe). ✓
- `plugin_register_normal_prefix_key` — alloc nullity checked,
  registry-vec nullity checked. ✓
- `_plugin_list_next` / `_plugin_list_prev` — clamped at
  count - 1 / 0 respectively. ✓ (verified by test)
- `_buf_load_file_into_active` — null path / FNF / FILE_TOO_LARGE
  all set typed `editor_last_error`. ✓
- `_render_list_overlay` — bounds check `n <= 0`; window-start
  clamp; cols truncation. ✓
- `_cyim_lsp_parse_refs` — uses flag pattern (`go = 1`) instead
  of `break` per CLAUDE.md cyrius conventions. ✓
- Built-ins-win-on-conflict for prefix-keys: verified by test
  (registering `(KEY_G, 'g', fp)` is shadowed by built-in `gg`). ✓

**Result:** ✅ no missed guards / off-by-ones / silently-ignored
errors. F-CO-3 is defense-in-depth, patch-sized when surfaced.

## 7. Security re-scan

Per CLAUDE.md security-hardening checklist, focused on what's
new in 1.4.x → 1.5.x:

| Surface | Status |
|---|---|
| `sys_system` uses | **0** (grep across `src/*.cyr` + `src/plugins/*.cyr` — none) |
| New `var buf[N]` declarations | All 8-byte i64 out-pointer slots, 40 / 64-byte static UI cstrings with explicit cap checks. No fixed-size buffers receiving caller-controlled-size data. |
| New syscall sites | None directly in cyim-source 1.4.x → 1.5.x changes. cyim-lsp 1.0.3's `/proc/self/environ` read is in the bundled distfile (audited at cyim-lsp's [`docs/audit/2026-05-06-audit.md`](https://github.com/MacCracken/cyim-lsp/blob/main/docs/audit/2026-05-06-audit.md) v1.0.3 amendment). |
| Unchecked pointer dereferences | None added; all `load8` / `load64` paths bounded. |
| Plugin ABI surfaces | `plugin_register_normal_prefix_key` validates registry + alloc; `plugin_buf_load_file` validates path + size + read; `plugin_list_display` accepts caller-owned items vec without copying (documented). |
| List-display dispatch interception | Captures all keys (returns ACT_NONE), buffer untouched (verified by test "dispatch swallows other keys without buffer mutation"). |
| Cross-file goto-def | `plugin_buf_load_file` uses cyim's existing `_cmd_e` path (audited at M7); the same dedup / FNF / size-cap guards apply. |
| URL-decoded paths | **NOT decoded** — `dest_path = uri + 7` strips `file://` only. Documented as F-CO-4 below; deferred from 1.5.x to a future patch. Not a security finding (no exploit path — the unmodified URI string is rejected by the OS open() if it contains percent-encoded bytes; cyim's filesystem ABI sees the raw URI bytes). |

**Finding F-CO-4 (LOW, UX):** URL-encoded `file://` URIs not
percent-decoded. Files with spaces / non-ASCII / emoji in paths
fail to load via cross-file goto-def or refs quickfix. Tracked
in roadmap.md's 1.5.x cycle deferred items. Patch-sized fix.

**No CRITICAL / HIGH / MEDIUM findings.** Trust model unchanged
(per [ADR 0001](../adr/0001-trust-model.md) — single-user, not
a privilege boundary). v1.0.0's M7 audit posture holds.

**Result:** ✅ clean.
