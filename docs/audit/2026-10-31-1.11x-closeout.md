**Shipped as v1.11.2**, the last patch of the 1.11.x line before 1.12.0.

This is the closeout pass from [`CLAUDE.md` § Closeout Pass](../../CLAUDE.md),
all 11 steps. It covers everything since the last closeout, 1.9.3, because
1.10.x shipped without one.

now CI gates.

## 2. Benchmarks (step 2)

**Not a baseline.** The host was shared at load average ≈ 20 on 16 cores
(another repository's qemu test loop). Every workload ran about 2× slower than
at 1.9.3, pure memory fills included, so absolute numbers from this run would
mislead.

What can be measured under load is a relative comparison: three alternating
rounds of 1.10.1 (built at its own pin, 6.6.2) and 1.11.2. The 1.9.3 toolchain,
6.5.35, is no longer installed. Each value is the median of the per-run
minimums.

| Bench | 1.10.1 | 1.11.2 | Δ |
|---|---:|---:|---:|
| `buf_fill_10MB` | 248.1 ms | 237.2 ms | −4 % |
| `buf_move_10K_cycles_10MB` | 92.7 ms | 90.6 ms | −2 % |
| `search_forward_10MB_worst_case` | 223.7 ms | 236.0 ms | +5.5 % |
| `search_forward_10MB_worst_case_ic` | 339.8 ms | 344.7 ms | +1.5 % |
| `render_build_line_80c_x1000` | 590 µs | 662 µs | +12 % |
| `highlight_buf_1MB_cyrius` | 644.8 ms | 580.3 ms | −10 % |

- **Search worst case:** the run ranges do not overlap. But `src/search.cyr`
  and `src/buffer.cyr` are unchanged since 1.10.1, so the change follows the
  toolchain (6.6.2 → 6.7.18), not cyim.
- **`render_build_line`:** the ranges overlap almost entirely (384–644 against
  360–680 µs). If any of the change is real, it is at most about 0.05 µs per
  line.
- **Search best case** is below the timer's resolution on both sides, so it is
  not compared.

**Carried:** a baseline taken on an idle host, now a maintenance item in the
roadmap.

## 5. Code review (step 5) — 7 findings

The diff since 1.9.3 got two review passes:
- one over the input path: `driver`, `agnos_kbd`, `mode`, `command`;
- one over the main loop, render and TTY: `main`, `render`, `tty`,
  `highlight`, `lang`, `cli`.

Each finding was confirmed by running code, except CR-5, which was inferred
from reading. The fixes were verified against the tests listed.

| # | Finding | Since | Status |
|---|---|---|---|
| CR-1 | **Arrows bypassed dispatch.** The decoder called `motion_apply` directly, and `motion_apply` has no mode guard. So an arrow on the `:` / `/` line moved the buffer cursor underneath, and a pending prefix survived the arrow: `g <Down> g` ran `gg`, `Ctrl-W <Left> j` ran `Ctrl-W j`. The comment over the call claimed the guard existed | ≤ 1.9.3; widened at 1.11.0, which sends every modified arrow down the same path | **Fixed.** Arrows are now `KEY_UP` … `KEY_LEFT` through `editor_step`, dispatched per mode like `KEY_DELETE`. `tests/feed.tcyr` +14; six fail on 1.11.1 |
| CR-2 | **The picker overlay ignored terminal height.** A fixed 10 rows on terminals as short as 2 placed rows at or above row 0. `tty_move` refuses those, so the items were drawn wherever the cursor was | 1.10.0 (live geometry) | **Fixed.** `_render_list_height`: at most 10 and at most `rows − 1`. `tests/render.tcyr` +5 |
| CR-3 | **The status row was not bounded by the width.** On the bottom row, the overflow autowraps and scrolls the screen every frame. Measured: 89 bytes on 40 columns | the path: always; made easy to hit by 1.10.0 | **Fixed.** `_render_status_compose` caps the row at `cols` (and the 1 KiB scratch). `tests/render.tcyr` +5, mutation-tested |
| CR-4 | **A per-frame leak.** `render_status` called `buf_new()` every frame: 128 bytes of bump allocation, never reclaimed | 1.3.5 | **Fixed.** One segment buffer, cleared each frame |
| CR-5 | **Any `epoll_wait` failure was treated as EINTR**, so a persistent error (EBADF) would redraw flat out | 1.10.0 | **Fixed.** Any error other than EINTR closes the watch and falls back to the blocking read. The read happens on the next pass, so no keys are dropped. Untested: an epoll error cannot be injected from outside |
| CR-6 | **rxvt's `$`-final keys.** `$` is an ECMA-48 intermediate byte, so `ESC [ 3 $` stays open and swallows the next key | 1.11.0 | **Filed as BUG-008**, for 1.13.0 with BUG-007. The fix risks misparsing a real `CSI … $ <final>` reply |
| CR-7 | **`tests/render.tcyr` assumed fd 0 is never a TTY**, and failed 3 assertions when run from a terminal | 1.10.0 | **Fixed.** `_query_winsize_fd`, and the test uses `/dev/null`. It passes inside a 50 × 132 pty |

**Reviewed and clean:**

- **Decoder state.** Every transition resets `feed_state` / `feed_plen`.
  `feed_pbuf` writes are bounded by `FEED_PBUF_MAX`. The lone-ESC rule holds,
  and ESC ESC at the end of a read dispatches two Escs.
- **The agnos decoder.** The count is clamped to `_KBD_SCBUF` (64, which
  matches `var scbuf[64]`). Worst-case output is 128 bytes against a 256-byte
  cap. The `E0` prefix carries across batches and is cleared once it is used.
- **`KEY_DELETE` in every mode and prefix branch.**
- **Every render scratch is bounded by its own size,** at the 1000 × 1000
  clamp ceiling too. The sanitizer never makes text longer. The UTF-8 chunk cut
  backs up correctly and always makes progress.
- **Signals.** The signalfd open and close order is nested, and the two masks
  are disjoint. Every failure path unblocks what it blocked, and the drain runs
  before the unblock. `--headless` closes its guard on every path.
- **Per-target calls.** The epoll_event data offset is 4 on x86_64 and 8 on
  aarch64. `sys_epoll_*`, `sys_readlink`, `xlseek` and `sys_nanosleep` each
  resolve to the target's own call.
- **CLI write lengths.** Re-decoded independently; all match.

**Observed, not a defect:** `window_navigate` lays out at a fixed 23 × 80,
while render uses the live size. Proportional layout keeps the two agreeing in
every case tried. It is on the roadmap's watch list.

## CI: the cross-targets are gated

The new `cross-targets` job builds `--agnos` and `--aarch64` and runs
`cyrius test --aarch64` under qemu-user. Locally the suite took 15 s on a
loaded host. Both cross-target breakages in cyim's history shipped because
nothing built or ran the other targets:
- the `--agnos` build was broken until 1.8.1;
- `:e` was broken on aarch64 through 1.10.1.

The AGNOS full-screen run stays out of CI, because it needs builds of agnos,
gnoboot and agnoshi.
