**Shipped as v1.11.0** (cyrius 6.6.2 → 6.7.9, darshana 1.0.0 → 1.3.0, BUG-003 …
BUG-006).

The security pass CLAUDE.md requires before every release, run against this
cut's two kinds of change: the dependency / toolchain move, and the four bugs
darshana's 2026-10-12 consumer survey filed. Because 1.11.0 was cut straight
from 1.10.1 (owner's instruction) rather than after a 1.10.x closeout patch,

**Result: the four filed bugs closed; three further defects found in the cut

## 1. Findings fixed in the cut

| # | Severity | Finding | Fix |
|---|---|---|---|
| A-1 | **MEDIUM** | **The editor died with its language server.** A write to the LSP server's stdin after the server exits raises SIGPIPE (default: terminate). ## 2. Residual — the LSP child inherits blocked signals

The resize watch (SIGWINCH, since 1.10.0) and A-1's guard (SIGPIPE) block
their signals, and a block survives `fork` + `execve`. The cyim-lsp bundle
spawns the server lazily, mid-session, with raw `fork` / `execve` and no hook
between them, so the server starts with both blocked. cyim cannot reach the
child, and dropping the guard around the spawn would reopen A-1 during the
handshake write (the server can die at start-up — measured: with a server
that exits at once, every edit re-spawns it). **Accepted for 1.11.0, with the
remedy upstream**: cyim-lsp should reset the child's mask (and SIGPIPE's
disposition) before `execve`, as the cyrius 6.7.9 stdlib exec family does.
Impact today: a language server with SIGWINCH and SIGPIPE blocked — the first
is inert for a non-terminal process; the second turns a write to a dead
client into EPIPE instead of termination. Recorded in
[`roadmap.md` § Dependency notes](../development/roadmap.md), with the
re-spawn-per-edit observation.

## 3. Reviewed and not changed

- **BUG-007 (filed, not fixed)** — SS3 (`ESC O P`: F1–F4) is not decoded:
  `<Esc>O` is a common typed sequence that lands in one read, so decoding SS3
  would eat a real command. Needs a decision on which risk to take.
- **Bracketed paste** — darshana 1.3.0 offers it; enabling it alone changes
  nothing (the decoder already swallows the markers). Its security value
  (a pasted ESC cannot run commands) needs paste semantics designed first.
  Deferred in the roadmap table.
- **Teardown order** — re-ordered to darshana ADR 0002 as amended at 1.1.4
  (cooked first, signalfds last). Against 1.10.1 with stdout a dead pipe,
  cyim died on its first write leaving the terminal raw; 1.11.0 exits 0 with
  the terminal cooked.
- **New syscalls**: none raw. The decoder, sanitizer and guard use stdlib /
  darshana wrappers (`sigprocmask` + `signalfd` inside darshana, `fcntl` via
  `fd_set_nonblocking`, `epoll_wait` with a timeout).
- **New buffers**: `feed_pbuf` (16 B in the editor record; writes bounded by
  `FEED_PBUF_MAX`, the count saturates past it); `_render_write_safe`'s 256 B
  scratch (writes bounded by `RENDER_SAFE_CHUNK`, output never longer than
  input); the status-segment scratch (1024 B, bounded by
  `RENDER_STATUS_BUF`). No stack buffer ≥ 64 KB (CI scan).
- **CI security scan** run locally: no `/bin/sh`, no `sys_system`, no raw
  `execve` / `fork`; the four M6 / M7 guards present.
