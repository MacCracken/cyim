## 3. Internal deep review (P(-1) step 3) — 2 findings

Walked the cycle's `src/` diff end to end. The logic-bearing changes are
`insert.cyr` (+84) and `cyimrc.cyr` (+103); the rest is dispatch wiring.

### C-1 — the config read cap fabricates a value (**LOW**) — FIXED

`cyimrc_load_path` reads at most 8 KB, then parses the trailing unterminated
bytes as a complete line. When the cut lands **mid-value**, the partial number
is applied — and because it is *shorter*, it can land back inside the valid
range and pass every validation layer added at 1.8.3.

Measured, with the fixture padded so the 8192-byte boundary falls inside the
digits:

```
file says:      palette.keyword = 199999     (out of range — correctly rejected when whole)
cyim applied:   palette.keyword = 19         (in range — silently painted)
```

The user gets a colour from a line that says something else, with no error
anywhere. **1.9.2 made this more reachable**, not less: cyim now reads *two*
config files, each with its own cap.

**Fix:** the trailing partial line is parsed only when the file fitted. If the
read hit the cap, those bytes are dropped — an over-cap config loses its last
line rather than misreading it. `CYIMRC_READ_CAP` is now named, and
`cyimrc_truncated()` reports the condition instead of leaving it silent.

Mutation-tested **in both directions**, which matters here because the
over-correction is as wrong as the bug: parsing the partial line always
reproduces the fabricated `19`; dropping it always breaks a legitimate
unterminated final line. Both fail, one assertion each.

### C-2 — two accessors with no caller anywhere (**coverage hole**) — FIXED

`cyimrc_home_applied()` / `cyimrc_local_applied()` were added at 1.9.2 so the
search-path precedence would be *observable*, and then nothing asserted on
them. The dead-code sweep flagged them as the only two symbols in the tree
with no caller.

Per [architecture note 004](../architecture/004-reading-the-dce-report.md),
that makes them a coverage hole rather than dead code — **the same shape as
`diag_msg` at 1.8.5**, and the second time note 004's check has earned its
keep. The fix is the test, not deletion.

Asserted as an **invariant** rather than against specific paths: the harness
runs against whatever `$HOME` and cwd it happens to have, so "did it find a
home config" is not knowable, but "the return value agrees with the flags" is
— and that is the actual contract. Plus a hermetic check that the flags
*reset* per load rather than accumulating, which is the part that would rot
silently.

### Reviewed and clean

- **`_cyimrc_join`** — `alloc(dlen + tlen + 2)` against a maximum write of
  `dlen + 1 + tlen + 1`. Exact, no slack, no overflow. The `load8(out + pos - 1)`
  trailing-slash probe cannot underflow because the function returns early on
  `dlen == 0` — the subtle case, and it is guarded.
- **`_cyimrc_home_path`** — refuses an empty `$HOME` / `$XDG_CONFIG_HOME`
  rather than building a path from it, so an unset variable **skips** the
  user-level file instead of reading `/.config/cyim/cyimrc`. Asserted.
- **`_insert_eol_pos`** — the 1.9.0 fix. Correct for 2-char, 1-char, empty and
  unterminated lines; all four asserted, and restoring the old `le == ls` test
  fails three of them.
- **`o` / `O` do not leak into VISUAL.** `editor_dispatch` handles VISUAL and
  VISUAL_LINE with their own explicit key tables rather than falling through
  to the NORMAL keymap, so `o` in VISUAL is a no-op, not an accidental
  line-open. (In vim `o` swaps the selection ends; cyim simply does not bind
  it there yet, which is a gap, not a bug.)
- **Undo and dot integration** — `o`/`O` join `_dot_begin` and
  `undo_record_pre_op` by action id, needing no special case, and both
  behaviours are asserted end to end.

## 4. External research (P(-1) step 4)

The relevant CVE corpus for what 1.9.x added is vim's **rc-file and
config-path** history, not its buffer-editing history.

| Class | vim's exposure | cyim |
|---|---|---|
| **Modeline RCE** | Repeated; the reason `modelineexpr` exists | **Refused by architecture** — no modeline, and buffer content is never parsed for commands |
| **`.exrc` from the cwd** | Answered with `exrc` + `secure`, off by default | **Decided at [ADR 0005](../adr/0005-cyimrc-cwd-trust-boundary.md)**: loaded, with the gate open, because the whole surface is ten colour indexes and three display integers — the worst a hostile directory achieves is a wrong colour. Held by a rule: every new key gets classified local-overridable or home-only |
| **Config value → memory corruption** | The generic shape | Closed at 1.8.3 (F-2) and re-verified here: every value is range-checked before reaching an index or a length, from **either** file |
| **Env-var path redirection** | `$HOME` / `$XDG_*` steering a config read | The env is the process's own, per [ADR 0001](../adr/0001-trust-model.md). See the residual below |

**The one thing worth naming:** `sudo cyim` with a preserved `$HOME` reads the
invoking user's config as root. That is vim's behaviour too, it follows
directly from ADR 0001 § 5 ("running cyim under sudo gives cyim root's
privileges, just like vim"), and the blast radius is a colour. Recorded as an
accepted residual rather than fixed — a `secure`-style ownership check would
guard nothing, because cyim has no dangerous subset to refuse.

## 7. Refactor pass (step 4) — considered, declined, recorded

**Four decimal-to-ASCII implementations** now live in `src/`:
`_buf_append_dec`, `_cmd_ls_put_int`, `_render_u16_ascii`, and agnos's
`_al_put_uint`. Each reverse-fills digits into a scratch and emits them
forward — the same five-line loop, four times. On count alone that is well
past CLAUDE.md's "wait for the third instance".

**Not merged, deliberately.** Their sinks differ in exactly the way that
matters:

| | Sink | Bound policy |
|---|---|---|
| `_buf_append_dec` | raw `store8` at a caller offset | none — caller sizes the buffer |
| `_cmd_ls_put_int` | through `_cmd_ls_put_byte` | bounds-checked per byte |
| `_render_u16_ascii` | raw `store8` | **domain clamp to 0..999, load-bearing** (audit F-2) |
| `_al_put_uint` | local buffer → `syscall(1, …)` | `#ifdef`-gated to agnos |

A shared core would be used four different ways, and its failure mode —
someone improving it and dropping the render clamp — is worse than the
duplication it removes. The duplicated part is the loop; the parts that carry
safety are precisely the parts that differ.

Recorded in [`roadmap.md`](../development/roadmap.md)'s watch list with the
count and the reasoning, so the next closeout has the data rather than
re-deriving it. **Trigger for revisiting: a fifth instance, or a bound bug in
any of the four.**
