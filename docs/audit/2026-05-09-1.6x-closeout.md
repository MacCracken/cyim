## 2. Benchmarks vs 1.5.3 closeout baseline (step 2)

| Bench | 1.5.3 | 1.6.8 | Δ | Notes |
|---|---:|---:|---:|---|
| `highlight_buf_1MB_cyrius` | 253 ms | **307 ms** | **+21%** | vyakarana 2.0.0 alloc-overhead; documented at 1.6.1, accepted trade |
| `highlight_buf_cache_hit_x1000` | 16 µs | 17 µs | +6% | sampling noise on the hot interactive path |
| `render_build_line_80c_x1000` | 253 µs | 265 µs | +5% | sampling noise on the per-line render path |
| `buf_fill_1MB` | n/a | 13.5 ms | new | not in 1.5.3 baseline |
| `buf_fill_10MB` | n/a | 140 ms | new | not in 1.5.3 baseline |
| `buf_move_10K_cycles_10MB` | n/a | 49 ms | new | not in 1.5.3 baseline |
| `search_forward_10MB_best_case` | n/a | 2 µs | new | not in 1.5.3 baseline |
| `search_forward_10MB_worst_case` | n/a | 106 ms | new | not in 1.5.3 baseline |
| `search_forward_10MB_worst_case_ic` | n/a | 167 ms | new | not in 1.5.3 baseline |

**Verdict:** the +21% cold-tokenize regression is the documented
vyakarana 2.0.0 trade — `tokenize_source(src, lang)` was a
single-call shape; the streaming primitive
(`tokenize_stream_new` + `_feed` + `_finish` + `_free`) costs
per-call alloc overhead until the rolling-buffer scanner lands
in vyakarana 2.x's perf opt window. cyim's call site has the
full source in memory (the gap-buffer), so it pays the alloc
cost without getting the streaming benefit.

Cold tokenize is **one-shot per file open** — not on the
interactive flow. Cache-hit (the hot path during editing) is
within sampling noise. **Acceptable to ship 1.6.x with this
regression**; revisit if vyakarana ships a 2.x perf bump.
