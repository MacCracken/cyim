# 2026-10-31 — cyim 1.12.1 release audit

**Shipped as v1.12.1.** `--expect=<pat>` / `--expect-not=<pat>`, the post-save
assertion `--write` and `--batch` already had, now also works on `--replace`,
`--replace-all`, `--replace-files` and `--replace-files-all`. Its parsing and
checking are now one implementation shared by all six verbs.

This is the security pass CLAUDE.md requires before every release. It covers
only what this cut changes.

**Predecessor:** [1.12.0 release audit](2026-10-31-1.12.0-audit.md).

**Result: nothing found.** The cut adds no input surface the CLI did not
already parse for two other verbs.

---

## 1. What is new

- **`_cli_parse_expect(arg, verb, st)`**, in `src/cli.cyr`, parses the two
  flags into a 24-byte record the caller zeroes. It replaces the two inline
  copies in `src/main.cyr`'s `--write` and `--batch` loops, and is called by
  the four replace parsers.
- **`_cli_check_expect(b, verb, pat, pol)`** checks the result after the save.
  It replaces the inline copies in `run_write` and `run_batch`. A third copy
  would have been needed for `run_replace`, which is CLAUDE.md's
  third-instance trigger.
- **`run_replace` / `run_replace_files`** take the pattern and polarity. The
  check runs after the save, or after an `--expect-N=0` no-op, before `--wc`
  prints.

## 2. Checklist (CLAUDE.md § Security Hardening)

1. **Input validation.**
   - **The pattern** is an argv string, used only as a literal needle for
     `_cli_count_matches`, which bounds-checks every match position against
     the buffer length (1.8.3).
   - **An empty pattern** is refused (exit 2), as on `--write`.
   - **The pattern is never echoed**, so the excerpt rules from 1.12.0 do not
     come into it.
2. **Buffer safety.**
   - **The parse record** (`var X_exp[24]`) is three 8-byte fields, all
     initialized before the loop. The constant-offset scan finds no access
     past 24.
   - **The two messages** go through the 1.12.0 helpers, which stop at
     `CLI_MSG_CAP`. The longest is `cyim --replace-files-all: --expect-not
     requires a non-empty pattern`, at 68 bytes.
3. **Syscall review.** No new syscall. The help text and usage lines changed
   length, and each literal's length was computed from its decoded bytes.
   `cyrius lint` is clean.
4. **Pointer validation.** The record's pattern pointer comes from `argv`,
   which lives for the whole process. It is read only when the polarity is not
   0.
5. **Command injection.** None.
6. **Path handling.** Unchanged.
7. **Write semantics.**
   - The assertion does not gate the write. A miss on a replace verb leaves the
     file saved and exits 6, exactly as on `--write` and `--batch`. This is
     documented in the usage guide and asserted by `tests/cli_smoke.sh`.
   - A caller who needs the write held back has `--expect-N` (checked before
     anything is written) and, when it lands, `--dry-run` (1.12.x).
8. **Compatibility.** An OLD or NEW argument that starts with `--expect=` or
   `--expect-not=` is now read as the modifier. That was already true of
   `--expect-N=`, `--regex=` and `--wc`. Everything that was valid before
   1.12.1 still parses the same way.
