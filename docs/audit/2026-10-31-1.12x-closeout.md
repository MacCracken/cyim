# 2026-10-31 — cyim 1.12.x closeout audit

**Shipped as v1.12.3,** the last patch of the 1.12.x line before 1.13.0.

1.12.3 also carries the line's last scheduled feature, `--replace-lines` /
`--batch-lines`. This document is both its release security pass and the
closeout from [`CLAUDE.md` § Closeout Pass](../../CLAUDE.md), all 11 steps, over
1.12.0 – 1.12.3.

**Predecessors:**
- [1.11.x closeout](2026-10-31-1.11x-closeout.md)
- release audits for [1.12.0](2026-10-31-1.12.0-audit.md),
  [1.12.1](2026-10-31-1.12.1-audit.md) and [1.12.2](2026-10-31-1.12.2-audit.md)

**Result: the code review found four defects and one documented trap. Three
defects are fixed in this cut with regression tests, and one is recorded for a
contract decision.**
- **The most serious is pre-existing.** A read error loaded as an empty or
  truncated file. Through the new `--replace-lines` it could delete lines and
  exit 0.
- **Everything else is clean:** benchmarks re-baselined on a quiet host, one
  consolidation (the shared modifier parser), the dead-code floor unchanged,
  and the security re-scan.

## 2. Benchmarks (step 2)

**A real baseline, the first since 1.8.6.** The host was idle (load average
0.7–0.9 on 16 cores). It is the current table in
[`BENCHMARKS.md`](../../BENCHMARKS.md).

- **Against 1.8.6:**
  - highlighting is −7 % (vyakarana 2.10.0);
  - `render_build_line` is +16 % (251 → 292 µs);
  - everything else is within 2.5 %.
- **Where the render step comes from.** Two alternating rounds, each tree at
  its own pin, on the same idle host: 1.10.1 measured 258–263 µs, 1.11.0
  281–282 µs, and 1.12.3 281–287 µs. So all of it arrived at 1.11.0, which
  changed both the toolchain (6.6.2 → 6.7.9) and the render path: C1
  classification by decoding (BUG-005), and `tty_fg_256_buf` validation
  (BUG-006). It costs about 20 ns per rendered line, about 1 µs per 50-line
  frame. Recorded, not pursued.
- **Search worst case** is flat at 103–104 ms across all three trees. The
  +5.5 % that the 1.11.2 A/B measured under load was noise.

## 4. Refactor pass (step 4) — one consolidation

**The shared modifiers.** 1.12.1 and 1.12.2 added `--expect` and `--dry-run`
handling to each writing verb. By 1.12.3, eight parsers each spelled out
`--wc[=l|=long]`, `--dry-run`, `--expect=` and `--expect-not=`, with their
duplicate-flag checks.

- **The change.** `_cli_parse_mods` handles all four into one 48-byte record.
  `_cli_dry_wc` takes the record. Each parser keeps only its own flags:
  `--expect-N` / `--expect-1`, `--regex`, `--fuzzy-edits`, `--all`,
  `--expect-first`.
- **How.** One mechanical transform, applied identically to all eight, with
  assertions that each removed block existed exactly once.
- **Size.** −259 / +120 lines, and −4,096 B on x86_64.
- **No change for callers.** The messages are byte-identical, and the 245 CLI
  smoke cases at that point pass unchanged, duplicate refusals included.
- **Earlier consolidations in the line:**
  - 1.12.1: `_cli_parse_expect` / `_cli_check_expect`, the third copy;
  - 1.12.3: `_cli_msg_pair` generalized to `_cli_msg_nth` for the
    `--batch-lines` triples.
- **Not merged.** The per-verb positional handling and usage lines. Their
  shapes differ: one, three, or a list of positionals. The 2.0.0 cmdit
  decision in the roadmap is where they would merge.

## 5. Code review (step 5)

An independent review of `git diff 1.11.2` over `src/cli.cyr` and
`src/main.cyr`, plus the new `src/diff.cyr`. Each finding was confirmed by
running a copied build, and each fix was then checked against the tests named.

| # | Finding | Since | Status |
|---|---|---|---|
| CR-1 | **A read error loaded as success.** `buf_load_file` ended its loop on `read() < 0` as on EOF and returned the bytes so far. A directory (EISDIR on read) loaded as an empty file. With `sub` a directory, `--replace-lines 1:2 sub f --expect-first=a` took it as an empty NEW, deleted lines 1–2 and exited 0. `--replace-files old sub f` deleted OLD the same way. A mid-file I/O error would truncate the buffer, which a replace verb could save over the whole file | the loader: always. Reachable through `--replace-files` since 1.1.4, and through `--replace-lines` at 1.12.3 | **Fixed.** A read error returns -1. CLI callers exit 3; `:e` and the plugin loader report an error. The editor's start-up callers ignore the result, so they behave as before. `tests/roundtrip.tcyr` +1, which fails on 1.12.2. `tests/cli_smoke.sh` +3 |
| CR-2 | **`--write --dry-run` misjudged its target.** It asked `file_exists`, which opens read-only. So an existing file it could not read counted as missing and was diffed from empty (a diff `patch` rejects). A missing file with empty stdin exited 1, "no change", although the write creates it. A directory produced a diff, where the real write fails | 1.12.2 | **Fixed.** The target is checked with `stat` (`_cli_path_kind`). A missing file is always a change (exit 0). A directory, device or FIFO exits 3, and so does an unreadable file. `tests/cli_smoke.sh` +4 |
| CR-3 | **`patch -p0` could not apply a dry-run diff for a path with a space.** The `---` / `+++` lines ended at the path | 1.12.2 | **Fixed.** The path ends with a tab, where GNU diff puts its timestamp, and `patch` reads up to it. `tests/diff.tcyr` pins the tab; `tests/cli_smoke.sh` +2 (a space path through `patch -p0`) |
| CR-4 | **A failed stdout write is ignored.** `cyim --replace --dry-run … > /dev/full` exits 0, "diff printed". `--grep` and `--wc` have the same gap, which predates 1.12 | `--grep` / `--wc`: before 1.12. `--dry-run`: 1.12.2 | **Recorded, not fixed.** Every exit code already means something on these verbs, and under `--dry-run` 1 means "no change". So the fix needs a contract decision first. It is a roadmap maintenance item |
| — | **CRLF and `--expect-first`.** Line A's `\r` is part of its text, and the mismatch message shows it as `?`, so copying `a?` back does not match | 1.12.3 | **Documented** in the usage guide (`--expect-first=$'a\r'`). Not a defect: the quote's sanitizing is deliberate |

**Reviewed and clean:**
- **Ranges and spans.** `_cli_parse_range` (zero, signs, A > B, a missing half,
  19 or more digits, trailing bytes). `_cli_line_span`, matching `--grep`'s line
  numbering.
- **Line verbs.** `_cli_put_lines` with empty NEW, NEW that is only newlines,
  and a range through a last line with no newline. The `--batch-lines`
  insertion sort and its adjacent-overlap check.
- **Token walking** on degenerate input, and exit-code precedence.
- **`src/diff.cyr`.**
  - **Myers:** trace indexing, V bounds and the backtrack.
  - **Diff output:** trimming, the fallback, and hunk merging.
  - **Headers:** zero-count starts and the no-newline marker.
  - **Tests:** 1,500 random small cases and 4,000-line cases past the cap, each
    applied by GNU `patch --fuzz=0`. On 200,000-line repetitive files it took
    about 0.1 s.
- **Message buffers** against `CLI_MSG_CAP`, and the sanitizer's byte budget.
- **`_cli_parse_mods`'s record** and its flag prefixes.
- **Every literal write length,** re-decoded by script.

## 7. Security re-scan (step 7)

| Check | Result |
|---|---|
| `sys_system(` / `"/bin/sh"` / raw `execve` / raw `fork` in `src/` | none |
| Constant-offset access past a fixed buffer (136 buffers in `src/`, `tests/`, `fuzz/`) | **0** |
| Stack buffers ≥ 64 KiB | none |
| Message buffers | all 8 `var msg[512]` carry `# must equal CLI_MSG_CAP`; every write into them is capped |

**The new surface at 1.12.3:**
- **What it reads.** `--replace-lines` reads a NEWFILE or stdin, and
  `--batch-lines` reads NUL-separated triples. Both use the readers `--batch`
  and `--replace-files` already use.
- **The range parser** accepts only `A:B`: digits, at most 18 per side, so no
  overflow, and `1 <= A <= B`. Everything else exits 2.
- **The line span** is computed in one pass with every offset inside the file.
  The range is used only after `B <= line count` is confirmed.
- **The batch arrays** are `alloc(N * 8)` for N triples counted from the input
  itself.
- **Echoed input** reaches stderr only through the sanitized, 60-byte
  `_cli_msg_excerpt`: the quoted line A on a mismatch, and a malformed range.
- **Atomic.** `--batch-lines` checks every triple, and every pair for overlap,
  before it builds the output, and saves once.
