# 2026-10-31 — cyim 1.11.1 release audit

**Shipped as v1.11.1** (cyrius 6.7.9 → 6.7.18; vyakarana 2.4.0 → 2.10.0,
darshana 1.3.0 → 1.7.0, cyim-lsp 1.5.3 → 1.5.4).

This is the security pass CLAUDE.md requires before every release. It covers
only what this cut changes:

- the toolchain and dependency move;
- the write-length defects the new toolchain's lint found;
- three grammar routes appended to the routing table.

No feature, syscall or input surface is new.

**Predecessor:** [1.11.0 release audit](2026-10-12-1.11.0-audit.md).

**Result:** the new toolchain found one LOW defect (B-1), fixed in this cut.
Nothing else is new. The 1.11.0 residuals stand (§ 3).

## 1. Finding fixed in the cut

| # | Severity | Finding | Fix |
|---|---|---|---|
| B-1 | **LOW** | **Literal writes one byte past the literal.** 24 usage and error messages in `src/cli.cyr` called `syscall(1, 2, "<literal>", N)` with `N` one more than the literal's byte length, so each wrote the literal's NUL terminator to stderr after its newline. Measured on 1.11.0: `cyim --grepfiles pat` ends its stderr `\n\0`. The extra byte is the literal's own terminator, so nothing is read out of bounds. But the write breaks its length contract and puts a stray byte on a stream that agent wrappers parse. The messages cover `--grepfiles`, `--grep`, the replace verbs, `--write` and `--batch`. Found by cyrlint's write-length rule (cyrius 6.7.11, widened at 6.7.12). | Each length set to the literal's byte count, checked against an independent decode of the literal (escapes and UTF-8 counted). `cyrius lint` is now 0 across `src/`, `src/plugins/`, `tests/` and `fuzz/`. `tests/perf.bcyr` had the reverse defect, cosmetic: one header was one byte short (its `×` is 2 bytes), so it dropped its newline. Fixed in the same pass. |

## 2. Checklist (CLAUDE.md § Security Hardening)

1. **Input validation.** No change to file loading, key decoding, the command line
   or `.cyimrc`. The CLI's only change is B-1's lengths. Exit codes are unchanged:
   `tests/cli_smoke.sh` passes 128 / 0.
2. **Buffer safety.** No new buffer in `src/`. cyrius 6.7.x's cyrlint adds
   constant-offset overrun checks on `var a[N]`, and they report nothing. The one
   new buffer is test-only: `tests/lang.tcyr` builds `./grammars/<name>.cyml` in
   `var gpath[128]`. The longest path is 28 bytes (11 + `asm_aarch64` 11 + 5 + NUL).
3. **Syscall review.**
   - **cyim's diff** adds no syscall. The 24 changed `syscall(1, 2, …)` lines change
     only their lengths.
   - **darshana 1.3.0 → 1.7.0** adds two AGNOS wrappers, `sys_console_mode` and
     `sys_fd_kind`. They are reachable only through `tty_isatty`, `tty_echo_off` and
     `tty_flush_input`, and cyim calls none of the three.
   - **darshana's new Linux code** (`tty_sgr_len`, `tty_sgr_strip_buf`,
     `tty_isatty_is_per_fd`, `tty_winsize_px`) is uncalled.
   - **vyakarana 2.4.0 → 2.10.0** introduces no syscall, `file_*` or `open*` call.
4. **Pointer validation.** No new dereference of untrusted input.
5. **Command injection.** No `sys_system` anywhere in `src/`. The LSP spawn is the
   cyim-lsp bundle's `fork` / `execve` with an explicit argv, unchanged since 1.5.3.
6. **Path handling ([ADR 0001](../adr/0001-trust-model.md)).**
   - **Grammar files.** The editor reads grammars from `<exe-dir>/grammars/` or
     `<exe-dir>/../grammars/`. They sit beside the binary and carry the binary's
     trust. vyakarana 2.10.0's parser accepts four new grammar keys from those files
     (`start_after`, `not_followed_by`, `number_float`, `char_literal`). All 49
     shipped files now load through that disk path in `tests/lang.tcyr`.
   - **The cwd fallback** (used when `/proc/self/exe` does not resolve) is unchanged.
     vyakarana's bootstrap serves its embedded copy of every grammar first, so a
     cwd `grammars/` is consulted only for a name the bundle does not embed.
7. **Known-CVE review.** No change to the escape-sequence, modeline or file-name
   surfaces. cyrius 6.7.18 fixes 13 audited issues (CYRIUS-2026-0038 – 0050).
   - None is in a module cyim compiles: async DNS, sigil, tls, X.509, ws_server,
     sandhi HPACK, bayan PDF, the Windows CLI, http, pam, and `file_write_atomic`,
     which cyim does not call because its atomic save is its own
     ([ADR 0006](../adr/0006-atomic-save.md)).
   - CYRIUS-2026-0046, the build's output temp file opened without
     `O_EXCL` / `O_NOFOLLOW`, hardens how cyim itself is built.
