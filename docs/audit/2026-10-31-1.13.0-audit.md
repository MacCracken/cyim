# 2026-10-31 — cyim 1.13.0 release audit

**Shipped as v1.13.0.** The CLI now reports a failed write to stdout: exit 7
where it used to exit 0. This closes CR-4 from the
[1.12.x closeout](2026-10-31-1.12x-closeout.md).

This is the security pass CLAUDE.md requires before every release. It covers
only what this cut changes.

**Result: nothing found.** The cut narrows a silent-failure path and opens
nothing.

---

## 1. What is new

- **`_cli_out(p, n)`** in `src/cli.cyr` writes all `n` bytes to fd 1. It loops
  over short writes, and a write that returns 0 or less records the failure in
  `_cli_out_failed`. After a failure it writes nothing more, so it cannot spin.
- **`_cli_out_str` / `_cli_out_dec`** are its string and decimal forms. The
  decimal goes through `_buf_append_dec` into a 24-byte scratch, at most 19
  digits.
- **Every stdout write in the CLI goes through it:**
  - the `--wc` report, which no longer uses `fmt_int`;
  - the `--grep` / `--grepfiles` lines and the `--context` separator;
  - the `--dry-run` diff;
  - `--help` and `--version`.

  The only direct `write(…, 1, …)` left in `src/cli.cyr` is `_cli_out`'s own.
- **`_cli_finish(verb, rc)`** wraps every CLI verb at `src/main.cyr`'s
  dispatch. It turns `rc == 0` into 7 when stdout failed, and says so once on
  stderr. Any other `rc` is returned unchanged, so a verb's own failure wins:
  under `--dry-run` an `--expect` miss stays 6.

## 2. Checklist (CLAUDE.md § Security Hardening)

1. **Input validation.** No new input.
2. **Buffer safety.** One new fixed buffer, the 24-byte decimal scratch, bounded
   as above. The stderr message goes through the `CLI_MSG_CAP` helpers.
3. **Syscall review.**
   - `write(2)` results on fd 1 are now checked. That was the point of the cut.
   - SIGPIPE is unchanged. The CLI does not block it, so a closed pipe ends a
     verb by signal, as for any filter (`cyim --grep x f | head -1` stays
     quiet). Exit 7 arises from errors such as ENOSPC, EIO, or EBADF for a
     closed stdout.
4. **Pointer validation.** Unchanged.
5. **Command injection.** None.
6. **Path handling.** Unchanged.
7. **Contract.**
   - **Exit 7 is new.** It is reachable only when a verb would have exited 0
     and its stdout output was lost. No existing code changed meaning.
   - **Success output is byte-identical to 1.12.3,** with the same exit codes.
     A 1.12.3 build and this one were compared on `--help`, `--grep` (with and
     without `--context`), `--grepfiles`, `--dry-run` and `--write --wc`.
   - **`~/.local/bin/cyim-edit`,** which mirrors the exit codes, needs to learn
     7.
