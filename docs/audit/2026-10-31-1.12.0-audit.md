# 2026-10-31 — cyim 1.12.0 release audit

**Shipped as v1.12.0.** This cut changes the agent CLI's failure messages:
- `--batch` names the failing pair;
- count failures report the count they found;
- "OLD not found" asks whether the edit is already applied.

No exit code, verb, modifier or file write changes.

This is the security pass CLAUDE.md requires before every release. It covers
only what this cut changes.

**Predecessor:** [1.11.x closeout](2026-10-31-1.11x-closeout.md).

**Result: nothing found.** The one new input-to-output path, the OLD excerpt,
is bounded and sanitized.

---

## 1. What is new

- **The messages are now composed, not literal.** `src/cli.cyr` builds each of
  the five changed messages in a 512-byte stack buffer (`CLI_MSG_CAP`) and
  writes it with one `write(2)` to fd 2.
- **Counts are printed.** `--expect-N`'s expected and found counts, and the
  occurrence count on a not-unique failure.
- **The `--batch` pair is identified:** `K/N`, plus a quote of the start of
  that pair's OLD.
- **An "already applied?" hint.** On "OLD not found", NEW is counted in the
  buffer: exactly once for unique-replace semantics, at least once for
  replace-all.

## 2. Checklist (CLAUDE.md § Security Hardening)

1. **Input validation.**
   - **Where the excerpt comes from.** The OLD excerpt is the caller's own
     stdin, but stderr may be a terminal.
   - **Sanitizing.** It goes through darshana's `tty_sanitize_buf` in UTF-8
     mode with only TAB kept. Every other C0 control, ESC always, DEL, C1, and
     any malformed UTF-8 becomes `?`.
   - **Length.** It is the first line only, at most 60 bytes. A cut backs up to
     a UTF-8 lead byte, so a split character does not turn into `?`.
   - **Tests.** `tests/cli_smoke.sh` feeds an OLD carrying `ESC [31m`, a second
     line and a 60-byte UTF-8 split, and asserts what comes out.
2. **Buffer safety.**
   - **The message buffer.** Every write into it goes through `_cli_msg_put`,
     which stops at `CLI_MSG_CAP`.
   - **Decimals.** `_cli_msg_dec` writes only when at least 20 bytes remain.
     `_buf_append_dec` writes at most 19 digits for an i64.
   - **The excerpt length** is clamped to the room left, minus 8 for the
     closing `..."`. The sanitizer never makes text longer, so its output fits.
   - **Worst case.** The longest message, a not-unique `--batch` pair with
     19-digit counts, a 60-byte excerpt and the hint, is under 300 bytes.
     Anything longer would be truncated, not overrun.
   - Both buffers are `var msg[512]`, commented `# must equal CLI_MSG_CAP`.
3. **Syscall review.** No new syscall. The changed sites are `write(2)` to fd 2
   with computed lengths, so the literal-length lint rule (1.11.1) no longer
   applies to them, and the cap bounds them instead.
4. **Pointer validation.**
   - `old_ptr` / `tok_ptr` are NUL-terminated in place by the batch tokenizer,
     as before. `strlen` on them is the existing contract.
   - The applied check runs `_cli_count_matches` on a literal NEW. The empty
     NEW is excluded first, because an empty needle has nothing to look for.
   - A regex NEW is never searched for: it can hold group references.
5. **Command injection.** None: no shell, no exec.
6. **Path handling.** Unchanged. File paths do not appear in the new messages.
7. **Known-CVE review.** The relevant class is **escape-sequence injection
   through echoed input**: terminal emulators have had CVEs for sequences
   echoed from untrusted text. The excerpt is the only echoed input, and it is
   neutralized as above.
8. **Cost.** The applied check costs one extra literal scan of the file, and
   only on the failure path.

## 3. Compatibility

- **Exit codes** are unchanged. `tests/cli_smoke.sh` asserts each one
  alongside the new text.
- **Stderr text** is not part of the contract (CLAUDE.md § Consumers).
- **Old wording, still present:**
  - `OLD not found in FILE`;
  - `count mismatch`;
  - `not unique`.
- **Old wording, now gone:**
  - `--batch`'s `pair OLD not found`, which now reads `pair K/N: OLD not found`;
  - `--replace`'s `occurs more than once`, which now reads `occurs N times`.

  A caller matching either exact phrase needs to update.
