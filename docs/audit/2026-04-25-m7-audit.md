# 2026-04-25 — cyim Security Audit (M7 — Pre-v1.0)

Second-pass security audit, paired with the external CVE corpus
survey at [`docs/security/2026-04-25-0day-corpus.md`](../security/2026-04-25-0day-corpus.md).
Re-walks CLAUDE.md's
[security-hardening checklist](../../CLAUDE.md#security-hardening-before-every-release)
with the corpus's 13 attack classes in hand.

> **CVE references verified.** All specific CVE numbers cited in
> the companion corpus document have been verified against
> primary sources (NIST NVD, MITRE CVE, vim/neovim GitHub
> Security Advisories, Red Hat / Ubuntu / SUSE bulletins). See
> the corpus document for citation links per class.

**Predecessor:** [2026-04-25 M5 initial audit](2026-04-25-security-audit.md)
— filed F-1 through F-6. F-1 / F-3 / F-4 closed in M6. F-2 / F-5 /
F-6 remain.

**Goal:** identify any remaining CRITICAL / HIGH findings before
v1.0; close them. Re-triage LOW findings.

---

## Methodology

Two-pass review:

1. **Internal review** — re-walk every `var buf[N]`, every syscall,
   every public function reachable from `editor_step` or `cyim
   <file>` startup. Cross-reference against the corpus survey.
2. **External corpus mapping** — for each of the 13 corpus attack
   classes, locate cyim's defense (refused-by-design / closed /
   open) and verify it.

Coverage cross-checks:

- [`tests/buffer.tcyr`](../../tests/buffer.tcyr) — 47 gap-buffer
  invariants
- [`tests/motion.tcyr`](../../tests/motion.tcyr) — 87 line-coord
  invariants
- [`tests/render.tcyr`](../../tests/render.tcyr) — 50 render
  invariants (includes 23 F-1 regression cases)
- [`fuzz/buffer.fcyr`](../../fuzz/buffer.fcyr) — 10 K random ops
- [`fuzz/tokenizer.fcyr`](../../fuzz/tokenizer.fcyr) — 100 K random
  bytes through the tokenizer
- [`fuzz/driver.fcyr`](../../fuzz/driver.fcyr) — 5 K random
  keystrokes through the full editor

## Checklist coverage

### 1. Input validation

| Surface | Status | Notes |
|---------|--------|-------|
| File content (`buf_load_file`) | **OPEN** | M5 F-2 — unbounded size. Fix in M7 bite 3. |
| Key escape sequences (dispatch) | CLEAN | Multi-byte handled via prefix state (Ctrl-w only); other ESC sequences treated as single-byte ESC + literal continuation. UX wart, not security. |
| Command-mode input (cmdbuf) | CLEAN | Capped at 4 KB in M6 (F-3). |
| Search pattern | CLEAN | Bounded by cmdbuf cap. Naive substring scan — no regex backtracking (corpus Class 2 refused). |
| Modelines | N/A | Not parsed (corpus Class 1 refused). |
| Embedded scripting | N/A | Doesn't exist (corpus Class 5 refused). |

**Result:** 1 OPEN (F-2, fixing in this milestone). 5 CLEAN. 2 N/A.

### 2. Buffer safety

Every static-size buffer reviewed:

| Location | Size | Consumer expects | Verdict |
|----------|------|-------------------|---------|
| `tty.cyr` `_tty_saved`        | 60 B   | Linux kernel termios ≤ 60 B | OK |
| `tty.cyr` `work` (in `tty_raw`) | 60 B | same | OK |
| `tty.cyr` `link` (in `_hl_resolve_dir`)  | 512 B | readlink(0) limit 511 + NUL | OK |
| `render.cyr` `out` (line buffer) | 8 KB | line + ANSI escapes; `byte_cap = out_max - 4` checked | OK |
| `render.cyr` `sbuf` (status line) | 1 KB | per-leaf status; visible-len tracked | OK |
| `command.cyr` `_cmd_ls_buf` | 4 KB | bounds-checked via `_CMD_LS_BUF_SIZE` | OK |
| `driver.cyr` `snap` (dot-replay) | 16 KB | overflow surfaces status (M6 F-4) | OK |
| `command.cyr` cmdbuf (gap-buffer) | grow-bounded | M6 F-3 cap | OK |
| Gap-buffer (general)             | dynamic | bounds-checked at every op | OK |

**Test coverage:**

- 47 buffer assertions cover gap migration edge cases
- 10 K random ops in `fuzz/buffer.fcyr` with cursor / buf_len
  invariants asserted every iteration
- Class 12 (memory corruption): closed-by-construction; no
  pointer arithmetic on attacker-controlled values.

**Result:** CLEAN.

### 3. Syscall review

| Syscall | Where | Args verified |
|---------|-------|----------------|
| `syscall(89, ...)` readlink | `highlight.cyr` `_hl_resolve_dir` | path = `"/proc/self/exe"` (literal), buf 512 B, count 511; result NUL-terminated explicitly |
| `syscall(16, fd, TCGETS, &buf)` ioctl | `tty.cyr` `tty_raw` | fd = stdin (0); buf = `_tty_saved` (60 B) |
| `syscall(16, fd, TCSETS, &buf)` ioctl | `tty.cyr` `tty_raw` / `_cooked` | same |
| `syscall(60, n)` exit | `main.cyr` | n is always 0/1/-1 from `main()` |
| `syscall(35, ts, 0)` nanosleep | `tty.cyr` `tty_probe` | 16-byte timespec; 50 ms sleep |
| `file_open` / `file_read` / `file_write` / `file_close` | various | go through `lib/io.cyr` arch-portable wrappers |

**Result:** CLEAN. All syscalls use literal paths or vetted args;
no untrusted input flows to a syscall without being copied first.

### 4. Pointer validation

| Surface | Status |
|---------|--------|
| Editor-state field access | All via `load64(s + N)` / `store64(s + N, v)` with literal offsets. No dynamic offsets. |
| Gap-buffer field access | Same — fixed offsets in 64 B header. |
| `bl_get` / `bl_buf` / `bl_path` | Bounds-checked against `vec_len`. |
| `highlight_kind_at` | Handles `tb == 0` (returns `TK_WHITESPACE`). |
| `editor_buf` returning 0 | Many handlers check `if (b == 0) { return 0; }`. Verified for `insert_apply`, `motion_apply`, `edit_apply`, `command_apply`, `search_apply`, `visual_apply`, `undo_apply`, `window_apply`. |

**Result:** CLEAN.

### 5. No command injection

`:!cmd` and `system()`-style shell-out are deliberately absent.
`grep` for `sys_system`, `sys_execve`, or any `:!` parser:

```
$ grep -rn 'sys_system\|sys_execve\|fn _cmd_bang' src/
(no matches)
```

Buffer-list `:e <path>` uses `sys_open` only — file content read,
no shell.

**Result:** CLEAN. Class 9 (format-string) also CLEAN — no
`printf`-family in the editor's output path; all output is direct
byte writes.

### 6. No path traversal

`:e <path>` accepts arbitrary paths. Corpus Class 11 — accepted at
the trust model level. cyim is an interactive local editor; the
user already has shell access. Documenting this in an ADR (see
M7 bite 3).

**Result:** DOCUMENTED. M7-4 below.

### M7 new findings

#### M7-1 [LOW] cfg_tabstop overflow when wired into render

**Class:** corpus Class 4 (integer overflow in command parsing).

**Where:** `command.cyr` `_cmd_arg_uint` parses `:set tabstop=N`
without bounding N. Today the value is stored in editor state but
not consumed by a loop bound — no exploit surface yet.

**Risk:** when `cfg_tabstop` becomes load-bearing in render (the
`docs/guides/cyimrc.md` deferred work for line-number gutter +
tab expansion), an unbounded N could drive negative-loop bounds
via overflow → memory write past line buffer.

**Recommendation:** at parse time (`_cmd_arg_uint`), cap at a
reasonable max — proposed `MAX_TABSTOP = 32`. cyimrc parser
should enforce the same.

**Triage:** LOW. Tracked for the bite that wires tabstop into
render. Not v1.0-blocking because the consumer doesn't exist yet.

#### M7-2 [LOW, deferred] User-grammar overlay supply-chain

**Class:** corpus Class 6.

**Where:** `cyimrc.md` mentions a future user-grammar overlay
search path. Not implemented today.

**Risk:** when implemented, an attacker who can write to the
overlay dir can substitute a malicious grammar. Worst case:
mistokenize security-relevant strings as comments, fooling the
user.

**Recommendation:** when overlays land, document the trust model
in the cyimrc.md / overlay bite. Match `.bashrc` / `.vimrc` model
(user-controlled = user-trusted).

**Triage:** LOW. Deferred — no overlay surface today.

#### M7-3 [LOW, accepted] TOCTOU on `:w`

**Class:** corpus Class 8.

**Where:** `command.cyr` `_cmd_w` opens the same path string at
save time. If the path was symlinked between load and save, the
write follows the new target.

**Risk:** in adversarial contexts (multi-user shared dirs,
`/tmp/`-style scenarios), an attacker swaps the symlink between
`:e` and `:w` to redirect the write.

**Mitigation considered:** open-once at load, hold fd, write back
through fd. Trade-off: file-handle pressure for editing many
files. Not adopted — matches vim's threat model.

**Triage:** LOW. Accepted with the trust-model note. If cyim ever
ships a setuid mode, this becomes a real concern.

#### M7-4 [LOW, accepted] `:e <path>` accepts arbitrary paths

**Class:** corpus Class 11.

**Where:** `command.cyr` `_cmd_e` passes user-supplied path to
`buf_load_file` → `sys_open` with no normalization or restriction.

**Risk:** in cyim's current threat model — interactive local
editor — this is fine. The user already has shell access; cyim
isn't a privilege boundary.

**Recommendation:** document the trust model in
`docs/adr/0001-trust-model.md` so future restricted-mode work
(daimon-driven sandbox) inherits the question explicitly.

**Triage:** LOW, accepted. ADR landing in M7 bite 3.

#### M7-5 [LOW, documented] Byte-vs-glyph column counting

**Class:** corpus Class 13 (Unicode parsing).

**Where:** `motion.cyr` (`motion_left`, `motion_right`,
`motion_up`, `motion_down`) and `buffer.cyr` (`buf_col_of`) all
work in byte offsets, not glyph offsets. A line with a 3-byte
UTF-8 character has column 3 at byte 3, despite being one glyph.

**Risk:** cosmetic / UX rather than security. Cursor positioning
is intentionally byte-oriented; matches vim with `:set
encoding=latin1`.

**Recommendation:** add a note to `docs/guides/usage.md` calling
out the byte-vs-glyph distinction. Proper Unicode column
counting is post-v1.0 demand-gated (would need a UTF-8 decoder
in the motion path).

**Triage:** LOW. Documented; not v1.0-blocking.

## Triage summary

| Severity | Count | Status |
|----------|-------|--------|
| CRITICAL | 0     | — |
| HIGH     | 0     | — |
| MEDIUM   | 0     | F-1 closed in M6 |
| LOW (open at end of M7) | 5 | M7-1 through M7-5; none block v1.0 |

**v1.0 gate:** the CLAUDE.md security-hardening rule says CRITICAL
and HIGH must be closed before v1.0. **Both are zero**. The five
remaining LOW findings are tracked with explicit rationale and
triage notes; they don't gate v1.0.

The audit's most useful single result: **5 of the 13 corpus
attack classes are structurally refused by cyim's design**. That's
the outsized win from refusal §0 — the absence of an embedded
scripting language, modelines, plugins, format strings, and a
regex engine eliminates the bulk of the historical CVE surface
without any defensive code at all.

The remaining classes either close-by-implementation (control-byte
substitution, bounds-checked buffers, naive scan) or accept-with-
trust-model (path traversal, TOCTOU on save) — both well-understood
positions for a local interactive editor.

## What this audit does NOT cover

- **Stdlib audit** — `lib/*.cyr` is vendored from the Cyrius
  toolchain. Per CLAUDE.md "Do not edit anything in lib/". Stdlib
  audit happens upstream in cyrius.
- **Compiler audit** — cc5 itself is the trust root for cyim's
  binary. Compiler-level audits (constant-time codegen, ASLR,
  etc.) are upstream.
- **Future restricted-mode** — daimon-orchestrated sandbox use
  inherits a different threat model. M7-4's ADR will document
  the open question.
