# 2026-11-11 — cyim 1.13.1 release audit

**Shipped as v1.13.1.** The screen now scrolls. This cut also adds the scroll
keys, decodes PgUp / PgDn, and fixes BUG-007 (SS3 keys) and BUG-008 (rxvt's
`$`-final keys).

This is the security pass CLAUDE.md requires before every release. It covers
only what this cut changes.

**Result: nothing found.** One latent bound of the 1.8.5 shape was closed in
passing (§ 2, item 3).

---

## 1. What is new

- **A view per window.** The 88-byte Window record gains `top` at offset 80
  (it was 80 bytes). The editor record gains `view_top` at 240 and `view_rows`
  at 248 for the tree-less path (it was 240 bytes; now 256).
- **`view_follow(top, cur, h)`**, a pure clamp. The renderer calls it every
  frame for every leaf, so `0 <= top <= cur`, and `cur - top < h`.
- **`view_scroll`**, the six scroll actions. It moves `top` and, when it has
  to, the cursor through `buf_move`. It never mutates the buffer, so it takes no
  undo snapshot and does not fire `post_change`.
- **The line walk.** `buf_next_line_start` and `buf_prev_line_start`, and
  `render_build_line_at` / `render_build_line_crlf_at`, which take a line's
  start offset instead of its number. `render_build_line` and
  `render_build_line_naked` are now wrappers, so the bounds arithmetic is still
  in one place. `render_line` had no callers left and was removed.
- **Decoder.** `ESC [ 5 ~` / `ESC [ 6 ~` become `KEY_PGUP` (261) /
  `KEY_PGDN` (262). A `$` ends a CSI whose parameters are digits only.
  `editor_feed_ss3` decodes a read of exactly `ESC O <final>`, and only the
  interactive loop's terminal reads call it.

## 2. Checklist (CLAUDE.md § Security Hardening)

1. **Input validation.**
   - Key codes past 255 have to be decided by every mode. A code that reaches
     a literal-byte default is stored by its low byte. For example, without the
     COMMAND branch's guard, PgDn appended a byte 5 to the command line.
     Mutation-tested: `tests/scroll.tcyr` fails 3 assertions when the guard is
     removed. Every mode handles `KEY_PGUP` / `KEY_PGDN` explicitly, and the
     picker swallows them.
   - `_feed_params_digits` reads at most `FEED_PBUF_MAX` (16) bytes. A
     parameter count past that means bytes were dropped, and is refused rather
     than read.
   - `editor_feed_ss3` reads 3 bytes, and only when `len == 3`.
2. **Buffer safety.**
   - New record offsets: `w + 80` in an 88-byte allocation, and `s + 240` /
     `s + 248` in a 256-byte one. Every Window is allocated by
     `window_new_leaf` / `window_new_split`, and every editor by `editor_new`.
     No caller builds either by hand, which was checked across `src/`,
     `tests/` and `fuzz/`.
   - Two `var out[8192]` line buffers, each bounded by `RENDER_LINE_BUF`
     (item 3). The single-view path reuses `render_build_line_crlf_at`, so the
     CRLF reservation is the 1.8.7 one.
   - Equivalence: walking by line start gives byte-identical output to drawing
     by line number, on every line of a fixture with empty lines, a Tab, a
     highlighted comment and an unterminated last line (`tests/render.tcyr`,
     +3).
3. **Bounds by a bare literal.** Through 1.13.0, `_render_leaf` passed
   `8192` as `out_max` beside its `var out[8192]`. That is the exact shape
   the 1.8.5 finding retired elsewhere: correct only while the declaration
   and the literal agree. It now passes `RENDER_LINE_BUF`. This was latent:
   the two values were equal.
4. **Pointer validation.**
   - `buf_next_line_start` reads only offsets `< buf_len`.
   - `buf_prev_line_start` steps back only from `ls > 0`, through
     `buf_line_start`, which stops at 0.
   - The render loop draws a line only while `top + line < n_lines`. For an
     empty buffer, `render_build_line_at`'s `blen > 0` guard reads nothing.
   - The cursor row is `cur - top`, which lies in `[0, h)` by `view_follow`.
     The existing clip to the leaf's last text row is kept.
5. **Syscall review.** No new syscall. The terminal read the SS3 rule depends
   on is the existing `file_read(0, &key_buf, 8)`. It is not applied on agnos,
   whose keyboard channel is not a read(2).
6. **No command injection.** Not applicable.
7. **Path handling.** Not applicable. No new path input.
8. **Known CVE corpus (escape sequences).** The decoder change widens what
   counts as a key, so the question is whether a terminal *reply* could be
   taken for one.
   - **The `$` rule.** The only standard reply with `$` before its final byte
     is DECRPM (`CSI ? Ps ; Pm $ y`, or `CSI Ps ; Pm $ y`). Both always have
     a `;` first, so neither is digits only. `tests/feed.tcyr` pins both
     shapes as swallowed. cyim sends no query, so it receives no reply anyway.
   - **The SS3 rule's risk.** While the editor is busy, a typed Esc, `O`, `P`
     can queue into one read. It is then swallowed as F1, so the keys are lost
     rather than run as a different command. `--headless` never applies the
     rule (`tests/integration_smoke.py`), so agent input is not affected.
9. **Cost as an availability question.** A frame stays linear in the buffer:
   one line count, one cursor-line scan, and about a screen of bytes walked.
   Measured on the 1 MB fixture: 5.6 ms per 22-row frame at the top, and
   9.4 ms at the end. An end-of-file frame drawn by line number instead costs
   105 ms (`BENCHMARKS.md`, 1.13.1).

## 3. Residuals

Unchanged from the [1.13.0 audit](2026-10-31-1.13.0-audit.md):

- The LSP child inherits blocked SIGWINCH and SIGPIPE (an upstream fix).
- R-1a: xattrs and ACLs are lost across the atomic save (blocked upstream).

The new BUG-009 (no sideways scroll) is a display gap, not a safety issue.
