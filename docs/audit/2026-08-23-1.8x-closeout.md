## 4. Refactor pass (step 4) — the render duplication

`render_build_line` and `render_build_line_naked` were **94.4% identical**: 73
and 69 code lines differing only in the tail reservation (`out_max - 6` vs
`- 4`) and the two CRLF bytes.

That duplication was load-bearing in the worst way. **The 1.8.3 audit had to
apply the same F-2 and F-3 bounds fixes to both copies** — and a future fix
landing in one and not the other would stay invisible until something overran.
Two implementations of the same bounds arithmetic is one more than can be kept
correct.

Collapsed: `render_build_line` is now a wrapper that hands `_naked` a budget
two bytes smaller and appends the CRLF itself. The reservation works out
identically — `_naked` reserves 4 for the colour reset out of `out_max - 2`,
giving the same internal cap of `out_max - 6`.

**Verified byte-identical across 46 cases** — 3 lines × 2 widths × plain and
highlighted × 5 buffer capacities from 20 to 8192, plus an empty buffer —
comparing the exact output bytes before and after. `src/render.cyr` 723 → 663
lines; binary −4,080 B.

One latent defect fell out of the rewrite: the old CRLF append was
**unconditional**, so an `out_max` under 2 wrote past the caller's buffer. Not
reachable (the two callers pass 1024 and 8192); guarded now.

## 5. Code review pass (step 5) — 2 findings

Walked the cycle's `src/` diff end to end (1.8.1..HEAD, 19 files, +950/−112),
looking for missed guards, off-by-ones and silently-ignored errors. The
logic-bearing changes concentrate in five files; the rest is documentation.

### C-1 — `sys_fchmod`'s return was discarded (**FIXED**)

In the atomic save path, `sys_fchmod(fd, mode)` carried the target's
permission bits onto the temp before the rename. Its return was ignored.

A failed `fchmod` meant **the rename proceeded at 0644** — a mode-600 file
coming back world-readable, with no error anywhere. Barely reachable (we own
an fd we just created), but a silent permission change is not a failure mode
to leave resting on a guess, and it is precisely the class the 1.8.3 audit was
written about.

Fixed, and the fix decides the right thing rather than just checking: "cannot
preserve the mode" is exactly what ADR 0006's in-place conditions exist for,
and the failure happens **before any write**, so it **falls back to writing in
place** rather than failing the save. The fchmod moved into `buf_save_file`
alongside the temp-create so that both pre-write fallback triggers sit in the
one function that owns the fallback decision — the invariant that *only*
pre-write failures may fall back is now visible in one place instead of split
across two functions.

Dropped a duplicate `stat` on the way: `_buf_save_can_rename` already had the
mode and now reports it through a slot, so a save costs one `stat`, not two.

### C-2 — the grammar-path buffer's bound spanned three functions (**FIXED**)

`_hl_load_one` wrote `<dir><name>.cyml` into a shared `alloc(1024)` scratch
with no bounds check. Safe by construction — `_hl_resolve_dir` caps readlink
at 511, `_hl_join_grammars` adds 9, the longest grammar name is 11, plus 6 for
the suffix and NUL = 537 — but that invariant was distributed across three
functions with no single place stating it, and the input is external (this
process's own path length).

Named as `HL_PATH_BUF` with the arithmetic written down, and `_hl_load_one`
now refuses rather than overruns. "Provably fine three call frames away" is
how F-3 got written in the first place.

### Reviewed and clean

- **`buf_save_file` / `_buf_save_atomic`** — every post-open failure path
  (`write`, `fsync`, `close`, `rename`) closes the fd and unlinks the temp. No
  fd leak, no temp leak, verified empirically across all failure modes.
- **`_buf_tmp_name`** — `alloc(plen + 48)` against a worst case of 9 + 7 (pid)
  + 1 + counter digits + 1. Comfortable.
- **`_buf_fsync_parent`** — path-split arithmetic correct for `"foo"` → `"."`,
  `"a/b"` → `"a"`, and `"/foo"` → `"/"` (the `dlen == 0` case).
- **`_buf_is_symlink`** — `probe[8]` with an 8-byte readlink cap. Exact.
- **`_cyimrc_palette_valid` / `_cyimrc_key_is_palette`** — the range check
  accepts exactly `-1` and `0..255`; the prefix test's `n <= 8` correctly
  rejects a bare `"palette."`. An unknown `palette.*` key is range-checked and
  then ignored, which is right.
- **Marks, `:ls` rendering, CLI input bounds** — re-walked, unchanged from the
  1.8.3 audit's findings, still correct.
